技术栈拆解

获奖站不是"用了 Three.js"这么简单，通常是一套组合拳。下面按你在项目里会遇到的顺序排列。

Three.js

渲染核心

把 WebGL 的底层 API 包成场景图。Camera、Scene、Mesh、Material —— 学会这四个概念就能开始做东西。当前版本 r186。

WebGL / WebGPU

底层图形接口

WebGL 是过去十年的标准；WebGPU 是新一代，性能与计算能力更强。Three.js 已支持双后端，可以渐进迁移。

TSL

着色器新写法

Three.js Shading Language。用 JS 写着色器，一次编写同时编译到 WebGPU 与 WebGL —— 不用再手写两套 GLSL。

GLSL

着色器语言

真正决定画面质感的层。粒子、溶解、流体、材质反射，都在这层。想要"研究级"的效果，绕不开它。

GSAP

动效时间线

事实标准。滚动触发、时间线编排、缓动曲线 —— 案例里那些"有导演的运动"，多半是它排的。

Lenis

平滑滚动

轻量的惯性滚动库。它负责把滚轮输入变成有重量感的位移，是 3D 滚动叙事的常见底座。

React Three Fiber

React 封装

用组件的方式写 Three.js 场景。适合产品页和作品集这类结构规整的项目；追求极致定制时，还是会回到原生 Three.js。

Blender / Spline

建模与产出

模型在三维软件里做，导出 glTF / GLB 进网页。Spline 是浏览器里的无代码 3D 工具，做简单场景很快。

学习路径

按顺序走。跳步是这个领域最常见的浪费时间的方式。

  1. 01

    先把基础图形概念打通

    坐标系、相机、投影、光照、材质。不需要写代码，先能在脑子里想象出"三维空间里发生了什么"。

    Three.js 官方手册 · 官方文档

  2. 02

    跟着系统课程走一遍

    碎片化教程最大的问题是缺上下文。找一门有完整项目的课，从头跟到尾，把整条链路走通一次。

    Three.js Journey（付费，公认入门首选）

  3. 03

    泡在官方 Examples 里

    几百个可运行示例，每个都能看源码。别通读 —— 带着具体问题去找，比如"我想要一个溶解效果"。

    Three.js Examples

  4. 04

    学着色器

    从"能改参数"到"能写出效果"的分水岭。这一步很慢，但跨过去之后你和普通前端就不在一个赛道了。

    The Book of Shaders · Shadertoy

  5. 05

    补上动效与滚动编排

    3D 只是舞台，让观众走完全程的是运动节奏。学会用时间线编排转场、用滚动驱动叙事。

    GSAP 官方文档 · Codrops 前沿 Demo

  6. 06

    解决"能跑"和"跑得好"的差距

    绝大多数人卡在这：本地很顺，一上手机就掉帧。压缩模型、压纹理、控制绘制调用、做降级方案。

    glTF Transform · Poly Haven（免费 HDRI / 贴图）· Sketchfab（模型库）

  7. 07

    去官方论坛提问

    遇到卡点先搜论坛，八成有人问过。提问时带上最小可复现示例，回复质量会高很多。

    Three.js 官方论坛 · GitHub 源码

什么样的站能拿奖

以下框架来自一位 Awwwards 评委的公开拆解。它同时也是你自己做项目时最好的自查清单。

01

艺术指导

有没有"一个观点"。获奖站不是被装饰过的模板 —— 每个字体选择、配色、栅格都在服务同一个想法。

自查：把动画全关掉，截一张静帧。它还好看吗？如果不好看，说明是动效在掩盖薄弱的美术方向。

02

被导演的运动

不是"为了动而动"，是编排。转场承载意义、滚动序列控制叙事节奏、微交互奖励注意力。

自查：盯着状态之间的过渡看，而不是盯着页面。廉价站是"切"，获奖站是"移"。

03

性能

这是大多数"还行"的站死掉的地方。评委是在真机上测的 —— 中端安卓掉到 18fps，就不会赢。

自查：DevTools → Performance → CPU 4 倍降速 + Fast 3G。还能守住 60fps 吗？

三项缺一项，分数就卡在中段。三项全中，才进入获奖区间。美感在 60fps 上成立 —— 这就是全部功课。
